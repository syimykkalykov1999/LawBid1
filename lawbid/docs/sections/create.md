# Паспорт: золотая кнопка «+» (посты, рилсы, кейсы)

Источник: репозиторий `LawBid`, `apps/mobile` (ветка `main` на 11.10) и открытый PR #111 (новый экран рилса, одобрен владельцем 08.10, в `main` ещё не влит).
Скриншотов и картинок-макетов не будет: владелец хочет смотреть и нажимать живую веб-сборку. Изменения показываем в ней (ссылку даст ветка каркаса).

Как заполнять: у каждого элемента в колонке «Решение» владелец пишет **оставить / убрать / изменить: …**.

Код:
- кнопка: `core/navigation/shell/main_shell.dart` → маршрут `/create` (`core/navigation/app_router.dart`)
- выбор: `features/create/presentation/screens/create_screen.dart`
- пост: `features/social/presentation/screens/create_post_screen.dart`
- рилс: `features/reels/presentation/create_reel_screen.dart`
- кейс: `features/cases/presentation/screens/create_case_screen.dart`, `widgets/case_wizard_steps.dart`, `widgets/case_photos.dart`, `application/create_case_controller.dart`
- сервер: `POST /posts`, `POST /videos/uploads`, вебхук `POST /bunny/:token`, `POST /cases`

## Экран 1. «Создать» (выбор)

Сверху крестик «Закрыть» и заголовок «Создать». Ниже большие карточки: круг с золотой иконкой, название, пояснение, стрелка.

| Роль | Карточки | Решение |
|---|---|---|
| Клиент | «Новый кейс» (Опишите ситуацию — адвокаты пришлют предложения.) · «Новый пост» (Поделитесь опытом или вопросом с сообществом.) · «Новая задача» (Заметка, звонок, встреча, документы — в ваш ежедневник) | |

Замечание по правилу 07.10 («на кнопках и карточках нет пояснительного текста, нет огромных карточек»): карточки выбора большие и с пояснениями. Владельцу решить.

## Экран 4. «Новый кейс» (только клиент)

Мастер из 5 шагов, сверху «Шаг N из 5» и полоска, внизу «Назад» / «Далее» (на последнем «Опубликовать»). Черновик хранится только на телефоне и сохраняется при каждом изменении.

| Шаг | Элементы | Решение |
|---|---|---|
| 1. О чём кейс | поиск по областям права, плитки категорий и подкатегорий, «Не уверен» (увидят адвокаты общей практики) | |
| 2. Опишите ситуацию | «Заголовок» (от-до символов), «Описание» (по решению 07.10 необязательно, но в коде есть проверка «минимум N символов», уточнить), подсказка «Не пишите контакты»; сервер отклоняет текст с контактами. Ниже «Фото и файлы»: до 9 фото или PDF/Word, видит только адвокат с принятым бидом. Не загрузившийся файл блокирует «Далее», пока его не повторят или не удалят | |
| 3. Где кейс | «Основной штат» (лист с поиском, 50 штатов + DC), «Город (необязательно)», «Добавить штат». После первых бидов штаты не меняются | |
| 4. Бюджет и срочность | «Указать сумму» / «Уточнить позже», сумма в USD. «Как скоро нужен адвокат?»: гибко / в течение месяца / скоро / срочно / очень срочно или «к дате» (суд, срок подачи, встреча, подписание, другое) | |
| 5. Проверьте и опубликуйте | строки со всеми ответами, нажатие на строку возвращает к шагу. «Обложка» кейса (готовые наборы, что видят адвокаты вместо клиента). Дисклеймер «LawBid не юридическая фирма». Золотой блок «кто что видит» (клиенты не видят, адвокаты видят, файлы закрыты). Для первого кейса галочка согласия на передачу контактов; без неё «Опубликовать» серая | |
| Закрытие мастера | лист «Сохранить черновик?»: «Сохранить» / «Удалить» / «Продолжить» | |
| Возврат к черновику | плашка «Мы восстановили черновик» + «Начать заново» | |
| После публикации | сообщение «Опубликовано» и сразу экран «Мой кейс» | |

## Мусор в коде

1. `main`: старый экран рилса с обрезкой видео (до 180 с исходника → кусок до 90 с), выбором кадра обложки в отдельном блоке, двумя полями «Заголовок» + «Подпись» и полосой загрузки внутри формы. Заменён в PR #111. Переносить только версию #111.
2. Переключатель «Пост / Новость», параметр `news` у экрана поста, строки `post.kind.*`, `post.news.*`: Новости выключены флагом с 06.10. Решить: убрать или держать за флагом.
3. Два почти одинаковых поля «заголовок + текст»: в посте (первая строка = заголовок) и в рилсе (`_OneField`). Сделать одно общее.
4. Своя модель загружаемого фото была в посте и в рилсе (`_Photo`); в #111 пост перешёл на общий `ComposerPhoto`, а рилс оставил свой `_InsidePhoto`. Свести в одну.
5. `ReorderableListView` с `// ignore: deprecated_member_use`.
6. Устаревшие комментарии: `bottom_nav_config.dart` («Stage 1.5…»), шапка `create_screen.dart` («адвокат: пост или Новость»).
7. Тексты мастера кейса (шаги 1–5) в коде есть только по-английски; русские приходят из таблицы переводов с сервера.

## Известные ошибки (исправлены, не повторять)

1. Видео 25 с появлялось через час: вебхук Bunny не доходил до сервера. Исправлено опросом Bunny раз в минуту (PR #109, в `main`). Владельцу проверить, приходят ли вебхуки вообще.
2. Рилс навсегда «в обработке», если в базе застрял статус `processing` после повреждённого восстановления: сервер публикует сразу.
3. Загрузка рилса не работала в браузерной сборке (исправлено в `main`).
4. Лимиты загрузки (число файлов, МБ, форматы) были зашиты в приложении. Теперь только из админки (bug 17).
5. Не загрузившееся фото кейса молча пропадало. Теперь блокирует «Далее» / «Опубликовать» до «Повторить» или «Убрать» (аудит 04.10).
6. Кнопка «Опубликовать» была просто серой. Теперь говорит, чего не хватает (07.10).
