# Паспорт: админка

Источник: `syimykkalykov1999/LawBid`, `apps/admin` (Next.js, ветка main на 11.10.2026). Решения владельца: `docs/decisions.md`, раздел 14.

**Как пользоваться.** В колонке «Пометка» напишите: **оставить**, **убрать** или **изменить: что именно**. Пустая пометка = «оставить как есть». Скриншотов нет: у админки нет демо-сборки, она работает только с живым сервером. Если нужны картинки отдельных экранов, скажите какие.

**Как устроена админка.** Одна админка на всё. В меню 9 разделов, в них 50 пунктов-вкладок: Дашборд, Люди, Галочки, Модерация, Кейсы, Деньги, Связь, Безопасность, Система. Права выдаются по областям («смотреть» / «управлять»). Деньги и ключи нельзя выдать никому, кроме супер-админа; «доверенный заместитель» только читает почти всё. Партнёр страны видит урезанный набор для своей команды. Все проверки прав на самом деле выполняет сервер, панель лишь прячет лишнее.

## Что нашлось в коде (сводка)
1. **Подписи над заголовками не совпадают с меню** на многих экранах («Система», «Люди», «Рост», «Контент» вместо реального раздела). Названия «Сотрудники», «Админы и права» вместо «Администраторы». «Поощрения» в меню открывают страницу «Лучший сотрудник».
2. **Права:** три экрана денег (Оплаты адвокатам, Рефералы, Партнёры) проверяют старые роли finance/support/moderator, а не права раздела. В «Партнёрах стран» нет режима «только смотреть». Часть кнопок видна при «только смотреть», а отказывает уже сервер.
3. **Бейдж «Обжалования отзывов» никогда не показывается** (счётчик не посчитан).
4. **Одно и то же настраивается в двух местах:** цена и пробный период (Цены и Планы), квоты (Хранилище и Загрузки), «Обязательная причина» лежит на странице Администраторов, а не в Настройках.
5. **Только США зашито в код:** штаты, реестры адвокатов, часовые пояса поддержки, «Реестр NY», хотя страны уже работают (решение «Не всё разделено по странам»).
6. **Вместо имени показан кусок ID** (проверяющий, админ в возвратах, «Выдал» в договорах, клиент без имени). В карточке заявки виден сырой JSON.
7. **Мёртвый код внутри файлов:** `PRICES`/`planPriceCents` (старые цены), `TRUST_LEVELS`, `FRAUD_STATUSES`, флаг `auto_bar_check`, код схемы с двумя банками в «Прибыли и резерве», страница-редирект `/legal`. Целиком неиспользуемых файлов нет.
8. **Дубли:** папка `components/legacy` живая (42 файла её используют), но у каждого компонента есть новый двойник; три копии `useDebounced`; «повторить после 2FA» написано заново в 6 местах; 5 страниц используют `window.confirm` вместо общего диалога.
9. `lib/api/demo.ts` (демо-режим партнёров) — временная прослойка: этих адресов нет в контракте API.
10. В «Промокодах» обещано «потом можно поменять лимит и срок», кнопки редактирования нет.

## Решения владельца, которые надо сохранить при переносе
- Вход по логину и паролю, 2FA по желанию (на экране входа она подана как обязательная, это ошибка текста).
- Владелец нигде не пишет «Причину»; для сотрудников владелец выбирает разделы, где она обязательна.
- Все ключи сервисов в «Безопасность → Ключи и сервисы», с подсказками простым словами, без перезапуска.
- Функции включаются в «Система → Функции», подписи простым языком.
- Подразделы в один ряд + «Ещё ▾»; названия ключей на двух языках.
- «Загрузки и файлы»: форматы, МБ и количество для каждого места загрузки.
- Лимиты админки меняются сами по нагрузке («Авто»); длинные списки разбиты на вкладки и поиск; суммы бывают дробными; карточки промокодов удаляются.
- Массовые действия, поиск, рабочие места по ролям и по стране.
- «Здоровье системы»: перезапуск, пауза тяжёлых задач, уменьшение серверов при перерасходе.
- Юридические тексты меняются в админке.
- Зарплаты и «Лучший сотрудник» начисляются сами; на карту владельца идёт только чистая прибыль.

**Не сделано (из решений):** убрать все лимиты для владельца; письма из «Привлечения» не подчиняются переключателю почты; не всё разделено по странам (споры, санкции, решения сотрудников).

Как держится сессия: после входа сервер кладёт токен в защищённую cookie `lawbid_admin` (JS её не видит, живёт 8 часов). Браузер общается только с самой админкой, а она пересылает запросы в API. Проверка в `middleware.ts` грубая — есть ли cookie вообще; настоящую проверку (подпись, сессия в Redis, роль) делает API на каждом запросе. «Выйти» завершает сессию на сервере и стирает cookie.
