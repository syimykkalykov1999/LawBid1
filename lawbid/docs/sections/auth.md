# Паспорт раздела: Вход, регистрация, выход

Источник: живой код старого репозитория `LawBid` (`apps/mobile/lib`, ветка main, 11.10). Решения владельца: раздел 1 в `docs/decisions.md`. Сайт (`LawBidSite`) входа не имеет, там только страницы документов (`/delete-account`, `/sms-consent`, `/terms`, `/privacy`).

**Как заполнять.** В колонке «Решение» владелец пишет одно из трёх: **оставить**, **убрать**, **изменить: …**. Пустая клетка значит «пока не решено».

**Скриншоты.** Появятся, когда поднимется веб-сборка старого приложения на демо-данных (ветка «Перенос LawBid в чистый репозиторий»). Пока на их месте пометка «скриншот: позже».

Тексты в таблицах взяты из файла переводов (русский столбец). Пометка «только в коде» значит, что ключа нет в `shared/localization/*.xlsx`, текст зашит в приложение (см. «Мусор», пункт 1).

---

## Путь пользователя

```
Заставка → Приветствие ─┬─ Телефон ─┐
                        ├─ Почта ───┼─ Код → Согласия → Роль → Контакты → Профиль → Уведомления → [адвокат: Лицензия, Практики, Подписка] → Тур → Лента
                        ├─ Apple / Google ┘
                        ├─ «Я помощник адвоката» → Код помощника → Профиль (имя) → Подключение к адвокату → Лента
                        └─ «У меня есть демо-код» → демо-сессия
```

Если человек закрыл приложение на середине, он вернётся на тот же шаг (шаг хранится на сервере). Порядок шагов решает один файл, `core/navigation/guards/app_router_guard.dart`.

## Правила, которые уже решены (из decisions.md, переносить как есть)

- Адвокат регистрируется в один шаг: штат + номер лицензии + клятва. Одобряется сразу, без запросов к сайтам коллегий.
- Сверка с реестрами только помечает расхождение для админа, сама не отклоняет.
- Один номер лицензии нельзя привязать к двум аккаунтам; номер заблокированного не регистрируется повторно.
- Забаненный клиент не создаёт новый аккаунт: проверяются телефон, почта, Apple ID, устройство. IP только показывается админу.
- «Вход и письма по почте» выключается одним переключателем в админке (сейчас ВЫКЛ). Основной вход по SMS.
- Ревьюеры магазинов и демо-коды проходят без шага почты; в демо не спрашивается код для истории дела, выгрузки данных и удаления аккаунта.
- Новые страны открываются в админке, сейчас только США.
- Лимит SMS на время теста: 100 в день всего, 10 на номер.

## Мусор в коде

1. **Переводы в двух местах.** Часть текстов этого раздела зашита в приложение (`core/l10n/static_translator.dart`, 2557 строк, и 29 файлов `core/l10n/strings/*.dart`), а в xlsx их нет: вход помощника, клятва адвоката, тексты шага «Лицензия», экран новых документов. В новом проекте все тексты должны быть в одном месте.
2. **Ссылки «Условия» и «Политика» на приветствии** ведут на заглушку «Этот способ входа пока не реализован (этап 1.4/1.7)». Сам текст заглушки тоже мусор.
3. **Необязательные согласия** (рассылка по почте, рекламные уведомления, аналитика) описаны в коде (`onboarding/domain/consent_type.dart`) и в переводах, но на экране их нет.
4. **Скрытые шаги мастера верификации** (вступление, фото лицензии, документ личности, селфи, камера с рамкой): больше 1000 строк кода, при текущих настройках не показываются. Решить, нужны ли они вообще.
5. **Старый путь помощника по номеру телефона** (экран подключения, текст «добавить ваш номер в «Команда»»), остался после перехода на вход по коду.
6. **Тестовая заглушка входа** `auth/data/stub_auth_repository.dart` (принимает любой код, кроме 000000). Сейчас только для тестов; в новом проекте может стать основой демо-режима без сервера.
7. В коде очень много длинных комментариев с историей решений и ссылками на старые документы (`file 07 §6.4`, `stage 1.7`, `OQ-048`). При переносе не копировать.
